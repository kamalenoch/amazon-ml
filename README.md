## Pipeline
```
TSVs ─► normalize ─► blocking (hashed multi-key IDF, top-K) ─► pair features ─► LightGBM ─► one-to-one selection ─► TSVs
        src/normalize.py   src/blocking.py                  src/features.py     src/matching.py            src/run.py
```
- **Normalize**: unidecode for Indic scripts & accents; legal forms (incl. transliterated "praivet limittedd") via a
  phonetic consonant skeleton; OCR digit fixes; EN/IN/FR address abbreviations; state detection; house numbers.
- **Blocking**: country-scoped hashed keys — name skeleton tokens, prefixes, token pairs, joined-name prefix
  (for `southernexports.com`), address tokens, number+token, token pairs, name×address cross keys. IDF-weighted,
  frequent keys (pool df > 600) dropped, union of top-30 total / top-10 name / top-10 address per S1.
- **Features**: rapidfuzz similarities, IDF-weighted Jaccard, rare-token-missing IDF, legal-form agreement,
  number overlap / conflict / near-typo, blocking scores, and competition context (how strongly a pool record
  prefers this S1 over its next-best S1 — the strongest signal).
- **Selection**: each S2/S3 record goes to at most one S1 (holds for 100% of train ground truth), then `p >= thr`.

## Run
**Kaggle (4 CPU / 30 GB), as parallel jobs** (see `notebooks/`):
- `kaggle_T_train.ipynb` (train normalization + blocking) and `kaggle_S_test_cands.ipynb` (test normalization + blocking) run in parallel (~75 min each);
- `kaggle_R_resume_train_predict.ipynb` imports both outputs, trains and predicts (~2 h), writes `output/`;
- `kaggle_pipeline.ipynb` runs everything in one job. Always run as *Save & Run All (Commit)*.

**Local / any Linux box (≥ 30 GB RAM):**
```bash
pip install -r requirements.txt
python -m src.run --data <student_resource>/dataset --work work --out output
python utils/validate_submission.py --matching output/matching_results.tsv \
       --candidate output/candidate_pairs.tsv --test-dir <student_resource>/dataset/test
```
Stages cache to `--work`; delete a file there to redo that stage. Useful flags: `--threshold`, `--train-frac`,
`--cap`, `--k-total`, `--rounds`.

**Fast iteration on a small dev subset (150k S1, runs on a laptop):**
```bash
python scripts/make_dev_subset.py <student_resource>/dataset/train devdata/train
# devdata/test/ -> symlink/copy the same files renamed test_source{1,2,3}.tsv
python -m src.run --data devdata --work work_dev --out out_dev --train-frac 1.0 --df-scale 15.2 --rounds 600
```
`--df-scale 15.2` makes blocking behave as on the full pool (key frequencies scaled to full size).

## Team workflow
1. Branch per idea (`feat/france-norm`, `feat/selection`, ...). Keep `main` = best known pipeline.
2. Log every run in `docs/experiments.md` (holdout F0.5, LB, what changed). One submitter at a time.
3. After editing `src/`, run `python scripts/make_notebook.py` to regenerate the Kaggle notebook.
4. Attach big outputs of a new best run to a new Release (`v2`, ...).
5. Final package: `scripts/package_submission.sh <team> <outputs_dir>`.

## Rules we follow
No external data, APIs, geocoding or lookups. Model: LightGBM (MIT). No pretrained models. Only provided files.
